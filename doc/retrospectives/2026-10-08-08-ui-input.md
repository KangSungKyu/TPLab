# UIContext P4 Modal/Input

2026-10-08. P4 adds logical modal eligibility, explicit focus, user-close approval and an optional native Input System adapter. Base TPLab.UI remains independent of Core.Input and Unity.InputSystem; the adapter lives in TPLab.UI.InputSystem and borrows an explicit runtime-clone InputManager, UI map, module and EventSystem.

Visible handles can change input mode, move their logical subtree forward, set focus to a target in their own view, and request a user close with Cancel, OutsidePointer or Button reason. UI-only modal gating works without Input System. When supplied, the modal factory provides an independently owned lease. User-close approval is opt-in; false vetoes, accepted close returns true after Closed, and forced close/owner shutdown bypass approval. Opening hooks may remember focus for application at Visible.

Native modal retirement keeps lower UI blocked through hide and cleanup, raw control release and a later EventSystem frame. This prevents the closing pointer/submit/cancel/navigation event from replaying into the newly exposed display. Middle modal B can close while modeless C retains eligible focus. Existing gameplay and transition leases remain independent. A native adapter fault transfers safe BlockAll ownership to UIContext through shutdown; Unbind does not release this owner protection or a live display's modal lease. DisplayChanged dispatch is synchronous/read-only and attempts every listener. Listener failures remain observable through the affected lifecycle completion after cleanup/lease retirement; SetInputMode, BringToFront and SetFocus command failures throw from those commands without poisoning a later close. These ordinary errors do not set Fault.
