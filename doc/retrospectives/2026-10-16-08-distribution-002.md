## 패키지 경계와 재현

기존 Core/Input/Editor를 유지하고 `com.tplab.ui`, `com.tplab.ui.inputsystem`, `com.tplab.netcode`를 추가했다. UI는 Core/UniTask/uGUI만 요구하며 Input System 연결은 별도 선택 adapter다. Netcode는 NGO/UniTask/Collections를 직접 선언하며 Core/UI/Input에 의존하지 않는다. UTP는 NGO의 전이 의존성으로 설치된다. UI/Input sample의 uGUI와 Netcode sample의 Input System/uGUI는 예제 선택 시에만 추가한다. Core의 CsvHelper/Addressables 경계와 기존 CLR 타입 소속은 이번에 분리하지 않았다.

깨끗한 detached worktree `tplab/worktrees/distribution-002`에서 `tools/build_distribution.py --source <clean-worktree> --revision <exact-SHA> --version 0.0.2 --run-id <unique> --output <worktree>/tplab/<unique>`로 생성했다. 앱 worktree 등록 도구는 과거 MyLab 경로를 Git 저장소로 인식하지 못해 동일 저장소의 Git worktree를 사용했다. `--prepare` 산출물을 검토 후 `upm/`에 반영하고, 후속 clean commit에서 `publicationSnapshot=Matched`를 확인했다. 후보 `f1d7cc67f5a7141f1b6c622a9347c5461032003f`에서 verify-03/verify-04의 6개 tgz bytes는 각각 동일했다. 생성 manifest의 `publishable=false`와 실행 gate `NotRun`은 생성기 자신의 증거 범위이며, 별도 소비 결과를 덮어쓰지 않는다.

package root의 package.json/README/CHANGELOG/LICENSE/Third Party Notices에는 package ID와 상대 경로에서 만든 결정적 GUID의 .meta를 생성했다. 기존 파일/폴더 GUID는 유지한다. Unity YAML 자산에 이미 있던 trailing whitespace는 원본 바이트 보존을 위해 정리하지 않았다. 새 생성 사본의 공백 경고와 실제 새 코드/문서의 공백 검사를 구분한다.

UI sample은 사전 작성된 transition asset의 `Assets/TPLab/Samples/UI/Scenes` 경로를 유지한다. 설치 안내는 Package Manager에서 sample을 import하고 Unity Project 창에서 전체 sample을 비어 있는 대상이 아닌 **아직 존재하지 않는** `Assets/TPLab/Samples/UI`로 명시적으로 이동하도록 정했다. GUID/asset bytes를 보존하며 다시 import하여 중복 GUID를 만들지 않는다. import 검증과 이 명시적 이동은 구분한다. Netcode sample은 실제 import 경로의 씬을 사용한다.
