# 03. 비동기·수명 — 현행 관행 초안

- [현행] 기준은 main `35508bc1fb8ed7749a292d1f9ae983b45387afd4`이며 이번 확인은 코드 읽기만 수행했다(컴파일·Unity·테스트 실행 0건); 아래 과거 실행 기록은 이번 실행을 대신하지 않는다. 근거: [공통 검증 범위](README.md#근거와-검증-범위), [IMP-03 README:3·63–78](../validation/imp-03/README.md#green회귀원본-보존).

[현행] 아래 설치 의존성 경로 표기는 manifest가 고정한 UniTask2.5.11의 Runtime 아래 파일:줄이다; 새 버전의 동일 동작을 가정하지 않는다. 근거: [manifest:3](../../Packages/manifest.json#L3), [해당 tag의 UniTaskExtensions](https://github.com/Cysharp/UniTask/blob/2.5.11/src/UniTask/Assets/Plugins/UniTask/Runtime/UniTaskExtensions.cs), 같은 Runtime의 UniTaskScheduler.cs·UniTaskCompletionSource.cs·UniTask.WhenAny.Generated.cs.

## 작업과 대기자의 수명

- [현행] UniTask를 쓰되 호출자의 대기 취소와 owner 작업 취소를 나눈다: `DataTableManager.LoadAsync`는 공유 작업에 owner token을 넘기고 caller에는 `AttachExternalCancellation`을 적용한다; `RootInstallation.PrepareAsync`도 공유 준비와 caller 대기를 분리한다. 근거: [DataTableManager.cs:306–326](../../Assets/TPLab/Core/DataTables/DataTableManager.cs#L306), [RootInstallation.cs:26–44](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L26).
- [현행] 취소 요청은 실제 작업 중지·해제 완료와 다르다: native resource는 Dispose 이후 늦게 완료될 수 있고 `ShutdownAsync`가 drain을 기다린다; 씬 전환도 이미 시작한 해제를 마친 뒤 token을 확인한다. 근거: [ResourceManager.cs:110–140·186–206](../../Assets/TPLab/Core/ResourceManagement/ResourceManager.cs#L110), [GameSceneManager.cs:826–830](../../Assets/TPLab/Core/SceneManagement/GameSceneManager.cs#L826).
- [현행] UI는 root·host·provider를 빌려 쓰고 display clone·구독·lease를 관리한다; 정상 root 종료는 UI installer의 `ReleaseAsync` 결과를 await한 뒤 Uninstall하며, prefab 공급자의 native 소유권은 UI로 넘어오지 않는다. 근거: [UIContextInstaller.cs:22–27·243–277](../../Assets/TPLab/UI/Runtime/UIContextInstaller.cs#L243), [UIContext.cs:459–465·1224–1294](../../Assets/TPLab/UI/Runtime/UIContext.cs#L459).

## 종료 timeout: 범위와 경계

- [결정됨] IMP-03의 기본은 **60초**, 단위는 초이며 finite 0/음수는 무제한이다; 양수는 TimeSpan 표현 범위여야 하고 NaN/Infinity/범위 초과는 mutation 전에 거부한다. 이는 이미 수락된 현행 계약이며 새로운 규칙 제안이 아니다. 근거: [IMP-03 README:51–57](../validation/imp-03/README.md#확정-계약과-남은-검증), [SceneOwnedRoot.cs:13·44–58](../../Assets/TPLab/Core/Lifecycle/SceneOwnedRoot.cs#L44), [RootInstallation.cs:223–244](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L223).
- [현행] deadline은 준비 취소 후 대기와 **각 installer의 역순 Release**에 독립 적용되며 `UnscaledDeltaTime`/Update를 사용한다; 정상 Prepare 대기나 shutdown 전체의 60초 상한은 아니다. 근거: [RootInstallation.cs:117–145·165–183](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L117), 테스트 `ShutdownTimeoutUsesUnscaledTimeWhenTimeScaleIsZero`, `EachReleaseReceivesAnIndependentTimeoutBudget`, `PreparationAndReleaseReceiveSeparateTimeoutBudgets`([AsyncSceneRootTests.cs:421·523·553](../../Assets/TPLab/Tests/PlayMode/AsyncSceneRootTests.cs#L421)).
- [현행] timeout 이후 남은 Release·Uninstall을 시도하지만 비협조 작업이나 main-thread blocking을 강제 중단하지 못한다; 공유 preparation이 canceled여도 `_preparationRunning`이 끝나기 전 CTS를 유지한다. 근거: [RootInstallation.cs:77–85·126–162·318–339](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L318), [IMP-03 README:57·78](../validation/imp-03/README.md#green회귀원본-보존).
- [현행] deadline 전 Release 오류는 Aggregate에 보존된다; deadline 후 오류는 `CaptureFailureAsync`가 Exception을 **정상 반환값**으로 바꾸고, timeout이 먼저 이긴 **WhenAny가 늦은 값을 채택하지 않아** 원인이 보고되지 않는다. capture 자체가 반환값을 버리는 것은 아니다. 근거: [RootInstallation.cs:132–139·165–197](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L165), 설치 UniTask 2.5.11 `Runtime/UniTaskExtensions.cs:415–455`, `Runtime/UniTask.WhenAny.Generated.cs:65–80`; 테스트 `LateReleaseFailureAfterTimeoutIsObserved`의 관측 범위는 [IMP-03 README:55](../validation/imp-03/README.md#확정-계약과-남은-검증)와 [AsyncSceneRootTests.cs:485–519](../../Assets/TPLab/Tests/PlayMode/AsyncSceneRootTests.cs#L485).

## Forget와 예외의 관측

- [현행] 개발 runtime의 `.Forget(...)`은 **17곳(Core8·UI Runtime8·UI InputSystem1)**이며 인자 없는 호출14·handler 지정3이다; Core의 handler2는 Bootstrap 로그, UI의 handler1은 shared prefab completion이다. Samples·Tests·Editor·Validation 및 upm 사본은 이 분모에 포함하지 않는다. 근거: [0.5단계 조사](README.md#05단계-사실-확인), [BootstrapSystem.cs:208·223](../../Assets/TPLab/Core/SceneManagement/BootstrapSystem.cs#L208), [UIContext.cs:437–441](../../Assets/TPLab/UI/Runtime/UIContext.cs#L437).
- [현행] 대표 worker는 본문 실패를 공유 completion에 전달한다(DataTable load, LoadedScene unload); GameSceneManager는 cleanup/callback 실패를 Aggregate하고 `LastFailure`와 completion에 전달하지만 finally와 개별 catch 밖 문장까지 하나의 try가 보호하지는 않는다. 근거: [DataTableManager.cs:357–395](../../Assets/TPLab/Core/DataTables/DataTableManager.cs#L357), [LoadedScene.cs:49–63](../../Assets/TPLab/Core/ResourceManagement/LoadedScene.cs#L49), [GameSceneManager.cs:599–632·1356–1377](../../Assets/TPLab/Core/SceneManagement/GameSceneManager.cs#L599).
- [현행] **UIContext.cs:437의 빈 handler는 전역 로그를 의도적으로 억제**하며 현재 awaiter의 오류 전달은 유지한다; InputSystem의 `RequestCancelAsync`는 UniTaskVoid로 owner/display 취소 OCE만 소비하고 나머지는 직접 로그한다. 근거: [UIContext.cs:436–443](../../Assets/TPLab/UI/Runtime/UIContext.cs#L436), [UIInputSystemAdapter.cs:309–323](../../Assets/TPLab/UI/InputSystem/Runtime/UIInputSystemAdapter.cs#L309).
- [현행] catch 밖 UniTask 실패는 설치 Forget/Scheduler가 publish하며 기본 OCE는 무시하고 subscriber가 없으면 Unity exception 로그로 보낸다; main Assets/Packages 소스에서 subscriber 등록은 발견하지 못했으나 실행 중 delegate/DLL 상태는 이번에 조회하지 않았다. 근거: 설치 UniTask 2.5.11 `Runtime/UniTaskExtensions.cs:552–619`, `Runtime/UniTaskScheduler.cs:18·41–94`, [0.5단계 조사](README.md#05단계-사실-확인).
- [현행] UI의 caller 취소 후 늦은 prefab 오류는 `ForwardPreparationAsync`의 실패한 TrySetException으로 소비되고, disposed root의 provider 오류는 cancellation으로 바뀐다; Prepare/Open/Close/CanClose hook도 `AttachExternalCancellation`이 먼저 끝나면 늦은 fault를 결과에 추가하지 못한다. 근거: [UIContext.cs:473–484·511–526·705–706·752–753·1019–1020](../../Assets/TPLab/UI/Runtime/UIContext.cs#L473), [UIContext.Input.cs:483–489](../../Assets/TPLab/UI/Runtime/UIContext.Input.cs#L483), 설치 UniTask 2.5.11 `Runtime/UniTaskExtensions.cs:255–268·314–326`, `Runtime/UniTaskCompletionSource.cs:150–172`.
- [현행] 정상 UI 종료는 ShutdownAsync를 await하지만 파괴 fallback은 BeginShutdown만 시작하고 Dispose는 이미 Faulted인 결과만 읽는다; 이후 Aggregate는 공유 결과에 남으며 미관측 ExceptionHolder의 GC 시점 로그 가능성을 즉시 로그 보장으로 바꿀 수 없다; 반면 RootInstallation의 늦은 Prepare 실패는 completion 전달 실패를 검사해 직접 로그한다. 근거: [UIContext.cs:389–409·1167–1174·1293](../../Assets/TPLab/UI/Runtime/UIContext.cs#L389), [UIContextInstaller.cs:249–277](../../Assets/TPLab/UI/Runtime/UIContextInstaller.cs#L249), [RootInstallation.cs:70–75](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L70), 설치 UniTask 2.5.11 `Runtime/UniTaskCompletionSource.cs:42–68`.

## 확정된 수명 규칙

- [결정됨] **D-H5 — 늦은 실패 계약.** timeout 후 늦은 실패 비채택과 UI의 취소 후 늦은 실패 소비 등 현행 계약을 문서와 XML에 명시한다; 이 가이드의 확정은 실제 XML 갱신 완료를 뜻하지 않는다. 빈 handler·timeout 후 원인·파괴 fallback의 서로 다른 관측 경로도 구분해 적는다. 근거: **사용자 2026-10-13 일괄 승인**, [사용자 결정](README.md#사용자-결정), 위 예외 경로([RootInstallation.cs:165–197](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L165), [UIContext.cs:437–440·473–484·511–526](../../Assets/TPLab/UI/Runtime/UIContext.cs#L437)).
- [결정됨] 검토했으나 채택하지 않은 대안: owner별 관측 callback·진단 저장 또는 코어의 늦은 원인 보관; 필요가 확인될 때 별도 IMP로 검토한다. 근거: 사용자 2026-10-13 일괄 승인(D-H5).
- [결정됨] **D-H6 — hook 작성자의 수명 책임.** 프로젝트 hook 작성자는 취소 token과 해제 수명을 준수하고 종료 후 해제된 서비스를 사용하지 않도록 자신의 작업을 관리한다; 현행 timeout이 hook 실행이나 main-thread blocking을 강제 중단하지 못한다는 한계를 계약에 함께 적는다. 근거: **사용자 2026-10-13 일괄 승인**, [사용자 결정](README.md#사용자-결정), [IMP-03 README:55·57·78](../validation/imp-03/README.md#확정-계약과-남은-검증).
- [결정됨] 검토했으나 채택하지 않은 대안: 코어가 늦은 오류 원인을 보관하는 안과 별도 늦은 오류 관측 테스트를 추가하는 안; 코어 보관은 D-H5에 따라 필요 확인 후 별도 IMP로 다룬다. 근거: 사용자 2026-10-13 일괄 승인(D-H5·D-H6).
- [결정됨] **D-H7 — root 단계별 deadline 유지.** 종료 timeout은 현재 root의 준비 취소 후 대기와 각 Release에만 적용하며 다른 native owner로 확대하지 않는다; ResourceManager의 pending native drain을 root timeout과 같은 완료 보장으로 표시하지 않는다. 근거: **사용자 2026-10-13 일괄 승인**, [사용자 결정](README.md#사용자-결정), [RootInstallation.cs:117–145·165–183](../../Assets/TPLab/Core/Lifecycle/RootInstallation.cs#L117), [ResourceManager.cs:110–140](../../Assets/TPLab/Core/ResourceManagement/ResourceManager.cs#L110).
- [결정됨] 검토했으나 채택하지 않은 대안: 다른 native owner까지 deadline을 확대하는 안. 근거: 사용자 2026-10-13 일괄 승인(D-H7).
