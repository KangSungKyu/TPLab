## 단위 작업 회고 상세 — 2026-10-13 이관

[결정됨] 사용자 A2 승인에 따라 기준 AGENTS의 회고 요건을 아래로 이관했다. 이관 당시 기록과 현재 지침을 구분하며, 현재 단위의 상세는 이 절을 따른다. 증거 요약의 단일 소유는 기존 D-E를 유지한다. 원문 기준: [AGENTS 51–56행](https://github.com/KangSungKyu/TPLab/blob/1ddc87d4116e9151f1b82836d664655d83270ba1/AGENTS.md#L51).

- [결정됨] 단위 작업은 설계·구현·검증·문서 변경처럼 독립적으로 결과를 검토할 수 있는 범위다. 각 단위의 완료·중단·차단 시, 최종 보고와 다음 단위 인계 전에 회고록을 작성한다. 단순 질의응답이나 도구 호출마다 회고 파일을 만들지는 않는다.
- [결정됨] 회고는 `doc/retrospectives/YYYY-MM-DD-NN-topic.md`에 저장하고 [회고 색인](https://github.com/KangSungKyu/TPLab/blob/af084e0d0027c4098fad08c336ccb0753e1c7862/doc/retrospectives/INDEX.md)에 날짜·주제·상태·링크를 추가한다. NN은 같은 날짜의 순번이다. 같은 단위의 보완은 해당 기록에 날짜를 명시해 덧붙이고, 별개의 후속 작업은 새 기록을 만든다.
- [결정됨] 목표·요청 범위와 기준 branch/HEAD, 실제 변경·핵심 결정 및 이유, 문제·원인·해결과 배운 점, 검증 결과·증거·미실행 영역, 미완료·위험·다음 작업과 선행 조건을 짧게 남긴다. 수행한 Git 작업과 남은 통합은 구분한다. 회고를 포함하는 최종 commit ID는 Git 이력과 최종 보고에서 확인할 수 있으므로 회고 자체에 필수로 적지 않는다.
- [결정됨] 확정·제안·미확정 및 구현 완료·초안·검증 대기를 구분한다. 실행한 테스트 수·실패·skip을 적고 실행하지 않은 검사는 미실행으로 기록한다. 기존 명세·코드·검증 자료는 링크로 참조하며 대화 전문·전체 로그·비밀값을 복제하지 않는다. 영속적인 API 계약과 작업 규칙의 본문은 기존 명세와 AGENTS.md가 소유한다.
- [결정됨] 다음 단위 시작 시 회고 색인에서 관련 시스템의 최신 기록과 필요한 선행 기록을 읽고 실제 checkout·diff·코드·증거와 대조한다. 과거 통과·승인·완료 기록은 현재 검증이나 새 권한으로 대신하지 않는다. 기록이 없으면 현재 확인 가능한 상태를 바탕으로 진행하며 전체 과거 회고를 임의로 복원하지 않는다.
- [결정됨] 중단·차단된 단위는 재개에 필요한 정보와 구체적인 다음 행동을 남긴다. 회고에서 발견한 개선안은 제안으로 기록하며 사용자 요청 범위를 넘어 구현을 자동 확장하지 않는다.

- [결정됨] 변경 하나의 증거 source·명령·환경·실행 수치·한계·실패 원문 요약·Actions 링크는 그 단위의 회고 한 곳에서 갱신한다(D-E). PR과 상태 색인은 회고를 링크한다. 새로운 validation README를 만들지 않는다. 기존 기록의 삭제는 별도 승인 범위에서만 수행한다. [증거 분류·원문과 최소 입력](07-validation-evidence.md#증거-분류와-원문-보존-상세--2026-10-13-이관)을 함께 따른다.
