# GC 할당 작성 가이드라인 (초안)

**상태**: 초안. 사용자 검토 전이다. [AGENTS.md](../AGENTS.md)와 충돌하면 AGENTS.md가 우선한다. 대상은 Unity 6000.3, C# 9 범위의 TPLab 코어(`Assets/TPLab/Core`, `Input/Runtime`)다. 근거 항목은 [IMPROVEMENT_BACKLOG.md](IMPROVEMENT_BACKLOG.md)의 IMP-05, IMP-11이다.

**근거 기준**: 코드 위치는 백로그 기준 `de879b9`(v0.0.1)이며, 지정 Core/Input 파일은 main `c1804e17` 기준으로도 변경이 없다(PR #4 대조). **검증 상태**: 코드 읽기 기준이다. 예시 경로의 실제 할당은 측정하지 않았다. **범위 밖**: `Assets/TPLab/UI`는 대상이 아니다. UI 적용은 이 가이드 확정(IMP-12) 뒤 IMP-13에서 정한다.

## 1. 원칙

- **경로의 호출 빈도로 규칙의 강도를 정한다.** 모든 코드를 할당 없이 쓰지 않는다. 읽기 쉬운 코드가 기본이고, 반복 호출되는 경로만 엄격히 한다.
- **측정 없이 P1/P2 경로를 최적화하지 않는다.** P0만 규칙으로 강제한다.
- **최적화가 계약을 바꾸면 안 된다.** 스냅샷 의미, 검증 순서, 예외 종류를 유지한다. 바꾸려면 사용자 결정이 필요하다.

## 2. 경로 분류

| 등급 | 정의 | 예 | 규칙 |
|---|---|---|---|
| P0 | 프레임마다 또는 소비자가 폴링할 수 있는 경로 | public 프로퍼티·`Count`·상태 조회, 풀의 대여/반납, `DataTableSnapshot.Get`, `MonoSingleton.Instance` | 정상 경로 할당 0. 할당 0 테스트 필수(8항) |
| P1 | 이벤트·전환 단위로 호출되는 경로 | 씬 전환 명령, 입력 레이어 획득/해제 | LINQ·컬렉션 생성 허용. 단 루프 안은 금지, 요청 하나에서 같은 계산을 여러 번 반복하지 않는다 |
| P2 | 로드·초기화 1회 경로 | 테이블 로드, CSV 파싱, 최초 에셋 로드 | 자유. 읽기 쉬운 코드 우선 |

새 코드를 쓸 때 등급을 판단하기 어려우면 P0으로 간주하고 보고서에 이유를 적는다.

## 3. 공개 API 규칙

- 프로퍼티와 `Count` getter는 **할당하지 않는다.** 스냅샷 복사를 프로퍼티로 노출하지 않는다.
- 컬렉션 스냅샷이 필요하면 `int XxxCount`와 `void GetXxx(List<T> buffer)`(호출자가 버퍼를 제공) 형태를 쓴다. 버퍼 메서드는 호출 전에 `Clear()`하는지 XML 주석에 명시한다.
- 이미 공개된 할당 프로퍼티는 제거하지 않고, XML 주석에 "호출마다 새 스냅샷을 만든다. 진단용" 이라고 적고 비할당 대안을 안내한다.
- 캐시로 해결하려면 무효화 조건이 **우리 코드의 변경 지점으로만** 정해질 때 한정한다. Unity 상태(`scene.isLoaded` 등 코드 밖에서 바뀌는 값)에 의존하면 캐시하지 않는다.

## 4. P0에서 금지하는 구문

| 금지 | 이유 | 대안 |
|---|---|---|
| LINQ (`Select`, `Where`, `Any`, `All`, `ToArray`, `Concat`, `OrderBy`, `SequenceEqual` 등) | 델리게이트·열거자·배열 생성 | 인덱스 `for` 루프 |
| `yield return` 이터레이터 메서드 | 호출마다 상태 기계 객체 | 직접 순회, 호출자 제공 버퍼 |
| `IEnumerable<T>`·`IReadOnlyList<T>` 등 인터페이스 타입으로 `foreach` | 박싱된 열거자 | `List<T>`/배열 타입으로 받아 `for` 또는 `foreach` |
| 캡처하는 람다, 메서드 그룹을 델리게이트로 변환(`All(IsPrepared)`) | C# 9에서는 호출마다 델리게이트 생성(캐시 안 됨) | 델리게이트를 필드에 한 번만 만들어 재사용, 또는 루프로 직접 호출 |
| 문자열 보간·연결·`string.Format`, `Enum.ToString()` | 문자열 할당 | 실패 경로에서만 생성(5항) |
| 박싱(구조체→`object`/인터페이스, `enum`→`object`) | 힙 할당 | 제네릭 제약, 구조체 직접 사용 |
| `new List<>`, `new HashSet<>`, `new T[]`, `params` 배열 호출 | 컬렉션 할당 | 필드의 재사용 버퍼, 호출자 제공 버퍼 |
| 배열을 새로 만드는 Unity API | 매 호출 배열 | `GetComponents<T>(List<T>)`, `Scene.GetRootGameObjects(List<GameObject>)` 같은 List 오버로드 |
| `try`/`catch`로 흐름 제어 | 예외 객체 생성 | `TryXxx` 패턴 |

## 5. 허용 패턴과 주의

- 인덱스 `for` 루프(`List<T>`, 배열), 구조체 열거자(`List<T>`의 `foreach`는 OK).
- 호출자 제공 버퍼, 필드에 둔 재사용 scratch 컬렉션. **재진입과 순서에 주의**한다. 이 저장소는 재진입 가드가 있는 곳(`ObjectPool`의 `_isBusy` 등)에서만 scratch를 쓰고, 사용 전 `Clear()`한다.
- 실패 경로에서만 문자열을 만든다. 예외 메시지 보간은 허용하되 정상 경로에서 미리 만들지 않는다. 로그는 조건 확인 후 호출한다.
- `async UniTask` 상태 기계는 구조체라 일반적으로 허용한다. 단 람다 캡처와 `AttachExternalCancellation`류의 취소 등록은 호출 빈도가 높으면 측정한다(IMP-11).
- 정렬·중복 제거가 필요하면 입력 크기가 작음을 확인하고 P1 이하에서만 쓴다.

## 6. P1·P2 규칙

- LINQ와 컬렉션 생성을 허용한다. 단 (a) 루프 안에서 반복 생성하지 않는다, (b) 한 요청에서 같은 값을 여러 번 계산하면(예: 전환 한 번에 `ValidateCommonLifetime`이 약 15회) 한 번 계산해 재사용하는 방법을 검토한다, (c) 실제 문제가 측정되기 전에는 가독성을 해치는 최적화를 하지 않는다.

### LINQ 사용 판단 절차 (D-04 채택)

LINQ를 쓰기 전에 "반드시 필요한가"를 아래 순서로 판단하고, 결과를 코드 리뷰·완료 보고에 한 줄로 남긴다.

1. 이 경로가 P0인가? 그렇다면 LINQ를 쓰지 않는다. 루프로 바꿀 수 있는지 먼저 검토한다.
2. P1/P2라면 루프로 바꿨을 때 가독성·정확성이 눈에 띄게 나빠지는가? 그렇지 않다면(조건 하나로 `Any`, 짧은 `Where` 등) 루프를 우선한다.
3. 정렬·그룹·집합 연산처럼 직접 구현이 오류를 부르는 경우는 LINQ를 쓴다. 입력 크기가 작고 호출 빈도가 낮음을 확인한다.

## 7. 정확성 우선

- 비할당으로 바꿀 때 입력이 같으면 결과도 같다는 것을 **기존 테스트의 재실행**으로 보인다. 새 동작이 필요하면 동작을 먼저 테스트로 고정한다(AGENTS.md TDD).
- 스냅샷 의미가 있는 API는 의미를 유지하거나 새 API를 추가한다. 의미를 바꾸는 변경은 사용자 결정 항목이다.

## 8. 측정과 테스트

- P0 경로를 만들거나 고치면 **할당 0 테스트**를 같은 단위에 추가한다.
  - 방법: 워밍업 1회 후 `GC.GetAllocatedBytesForCurrentThread()`를 N회 호출 전후로 비교해 차이가 0인지 단언한다. 다른 스레드 영향은 없지만 Editor에서는 잡음이 생길 수 있다. 0이 안정적으로 나오지 않으면 임계값을 임의로 정하지 말고 보고한다.
  - 대안: `Unity.Profiling.ProfilerRecorder`(내장, 패키지 불필요)로 프레임 GC 할당을 읽는 방법. 에이전트가 사용 가능 여부를 확인하고 증거를 남긴다.
- 새 패키지(Performance Testing 등)는 사용자 승인 없이 추가하지 않는다(AGENTS.md).
- 측정 결과는 개발 Editor 기준임을 보고에 적고, IL2CPP·모바일은 미검증으로 표시한다.
